# GPG Meister 1.0.2 Security Fix List

Status: verified
Scope: local, non-destructive codebase review for secrets, vulnerabilities, and misconfigurations.

## Fixes

- [x] High: Reject unsafe `config.toml` permissions before loading trusted settings.
  - Files: `src/gpg_meister/app.py`, `src/gpg_meister/services/config_service.py`, `src/gpg_meister/startup/environment_check.py`, `src/gpg_meister/storage/permissions.py`
  - Issue: `config.toml` is loaded before the startup permission check. `check_config_permissions()` also handles only group/world-readable states, but `permissions.report()` returns group/world-writable first, so mode `0666` currently yields no warning. A writable config can tamper with `gpg_binary_path` and `gpg_binary_trusted_hash`.
  - Fix: check and reject group/world-writable config files before `config_service.load()`, handle all unsafe `PermissionStatus` values, and immediately chmod or fail closed.

- [x] Medium: Fix broken `install.sh` shebang.
  - File: `install.sh`
  - Issue: line 1 contains text before `#!/usr/bin/env bash`, so the script is not a valid shell script entrypoint.
  - Fix: make the shebang the first bytes of the file.

- [x] Medium: Replace `curl | sh` installer flow for `uv`.
  - File: `install.sh`
  - Issue: `curl -LsSf https://astral.sh/uv/install.sh | sh` executes remote code without pinning or signature verification.
  - Fix: use package-manager install, pinned release asset plus checksum/signature, or document a manual verified install.

- [x] Medium: Cap KDF cost for untrusted vault imports before running Argon2.
  - Files: `src/gpg_meister/models/kdf_params.py`, `src/gpg_meister/models/vault.py`, `src/gpg_meister/services/vault_service.py`
  - Issue: untrusted vault headers can request up to 2 GiB memory and 20 iterations before authentication, causing local DoS.
  - Fix: enforce a lower import-time ceiling, ideally at or below the strongest supported app profile.

- [x] Medium: Auto-clear clipboard for decrypted plaintext and other sensitive outputs.
  - Files: `src/gpg_meister/ui/messages/decrypt_view.py`, `src/gpg_meister/ui/messages/encrypt_view.py`
  - Issue: direct `QApplication.clipboard().setText(...)` calls bypass the configured clear timer.
  - Fix: route sensitive copies through one central clipboard helper using `clipboard_clear_seconds`.

- [x] Medium: Block revoked and expired recipients before encryption.
  - Files: `src/gpg_meister/ui/messages/encrypt_view.py`, `src/gpg_meister/ui/messages/encrypt_viewmodel.py`, `src/gpg_meister/services/message_service.py`
  - Issue: recipient cards mark revoked/expired keys visually, but `_update_encrypt_button()` only checks that recipients exist, text is non-empty, and the confirmation checkbox is checked. `always_trust` is then passed through when the user confirms.
  - Fix: disable encryption for revoked keys and require an explicit, separate policy decision for expired keys; enforce the same rule in the service layer, not only the UI.

- [x] Low: Check vault file size before `read_bytes()`.
  - File: `src/gpg_meister/services/vault_service.py`
  - Issue: the vault parser has ciphertext/header limits, but the whole file is read into memory before those limits are applied.
  - Fix: use `stat().st_size` and reject files larger than the maximum frame size before reading.

- [x] Low: Harden `.sha256` sidecar parsing.
  - File: `src/gpg_meister/services/vault_service.py`
  - Issue: `split()[0]` can raise on empty/malformed sidecar files and does not validate checksum format.
  - Fix: read a bounded amount and require a 64-character hex digest.

- [x] Low: Remove unused import reported by ruff.
  - File: `src/gpg_meister/ui/messages/share_key_view.py`
  - Issue: unused `Qt` import.
  - Fix: remove the import or use it intentionally.

- [x] Medium: Harden trusted GPG binary pinning against parent-directory and TOCTOU attacks.
  - Files: `src/gpg_meister/startup/gpg_detector.py`, `src/gpg_meister/app.py`, `src/gpg_meister/services/gpg_service.py`
  - Issue: the detector hashes the binary and rejects group/world-writable binary files, but it does not validate parent-directory writability/ownership and does not re-check the hash immediately before later GPG executions.
  - Fix: validate every parent directory up to a trusted root, reject group/world-writable parent directories, store inode/device metadata where available, and revalidate the hash in `GPGService.__init__` before constructing `gnupg.GPG`.

- [x] Medium: Bind the stored trusted GPG hash to the stored trusted path.
  - Files: `src/gpg_meister/models/config.py`, `src/gpg_meister/app.py`, `src/gpg_meister/startup/gpg_detector.py`
  - Issue: `GPGBinaryTrust` stores both `path` and `sha256`, but detection only consumes the hash. The path field is not used to detect path substitution or stale trust metadata.
  - Fix: require `gpg_binary_trusted_hash.path` to equal the canonical override path before accepting the pin, then persist canonical path plus hash together.

- [x] Medium: Limit untrusted public-key import size and key count.
  - Files: `src/gpg_meister/ui/keys/public_key_import_view.py`, `src/gpg_meister/services/key_service.py`
  - Issue: public-key files and pasted armored input are read/scanned/imported without app-level size or key-count limits.
  - Fix: enforce a maximum armored input size, reject binary blobs in the public-key dialog, and cap the number of keys per import batch.

- [x] Medium: Reject or explicitly route private-key material in the public-key import dialog.
  - Files: `src/gpg_meister/ui/keys/public_key_import_view.py`, `src/gpg_meister/services/key_service.py`, `src/gpg_meister/services/gpg_service.py`
  - Issue: `plan_import()` records `has_private_key`, but the UI does not surface or block it, and `_do_import()` imports the original armored block through `import_armored()`. A private key block can therefore be imported through a dialog labelled "Public Key".
  - Fix: detect `-----BEGIN PGP PRIVATE KEY BLOCK-----` and `has_private_key=True`, block in this dialog, or redirect through a private-key/vault import flow with stronger warnings and audit metadata.

- [x] Medium: Flag or block weak/legacy imported key algorithms and lengths.
  - Files: `src/gpg_meister/services/gpg_service.py`, `src/gpg_meister/models/key_info.py`, `src/gpg_meister/ui/messages/encrypt_view.py`
  - Issue: key generation enforces modern algorithms/lengths, but imported/listed keys are accepted as-is. GnuPG algorithm 17 (DSA) is surfaced as `ECDSA`, and unknown algorithms default to `RSA`, which can hide legacy or unsupported key types in the UI.
  - Fix: model legacy/unknown algorithms explicitly, preserve raw GnuPG algorithm IDs, warn or block encryption/signing for DSA, RSA below policy floor, expired, revoked, or unsupported keys.

- [x] Medium: Shorten UI passphrase lifetime in viewmodels and wizard pages.
  - Files: `src/gpg_meister/ui/keys/key_create_viewmodel.py`, `src/gpg_meister/ui/vault/vault_export_viewmodel.py`, `src/gpg_meister/ui/vault/vault_import_view.py`, `src/gpg_meister/ui/messages/decrypt_viewmodel.py`, `src/gpg_meister/ui/messages/sign_viewmodel.py`, `src/gpg_meister/ui/messages/encrypt_viewmodel.py`
  - Issue: passphrases are first held as Qt/Python strings and then copied into immutable `bytes` captured by worker closures. Some flows leave the UI field populated until success/error or wizard completion.
  - Fix: clear UI fields at submit time, avoid storing passphrases in viewmodel attributes where possible, prefer one-shot getter handoff, and use mutable buffers only where Python allows best-effort zeroing.

- [x] Medium: Stop surfacing raw exception strings to users.
  - Files: `src/gpg_meister/ui/worker.py`, `src/gpg_meister/ui/*`, `src/gpg_meister/services/*`
  - Issue: `Worker.run()` emits `str(exc)`, and many views display it directly. GPG/status errors and filesystem errors can expose local paths, binary locations, fingerprints, or operational details in the UI.
  - Fix: map exceptions to typed user-facing errors through `ui/errors/error_catalog.py`; log detailed diagnostics separately after sensitive-data filtering.

- [x] Medium: Add manifest/key-count/string-length limits after vault decryption.
  - Files: `src/gpg_meister/models/vault.py`, `src/gpg_meister/services/vault_service.py`
  - Issue: `VaultManifest`, `VaultKeyEntry.user_ids`, `public_key_armored`, `private_key_armored`, `description`, and `created_by` lack explicit length/count bounds. A validly encrypted but malicious vault can force large UI/model allocations within the 256 MiB ciphertext ceiling.
  - Fix: cap key count, user-id count, user-id length, description length, and armored block size; reject inconsistent `has_private_key=True` with missing private key material.

- [x] Low: Fix vault import preflight magic check.
  - File: `src/gpg_meister/ui/vault/vault_import_view.py`
  - Issue: the UI reads the first 16 bytes and searches for `GPGMEISTER_VAULT`, but the binary frame starts with `GPGV` and the format tag is inside the JSON header later in the file.
  - Fix: check the `GPGV` magic or call the vault frame parser in a cheap metadata-only mode.

- [x] Low: Avoid build-time dependency download via `setup_requires`.
  - File: `packaging/macos/setup.py`
  - Issue: `setup_requires=["py2app"]` can trigger implicit build-time dependency resolution.
  - Fix: move build tooling into an explicit locked packaging environment.

- [x] Low: Remove `assert` from runtime security/control-flow paths.
  - Files: `src/gpg_meister/app.py`, `src/gpg_meister/storage/file_lock.py`
  - Issue: `ruff --select S` reports asserts in app control flow. Python optimization (`-O`) removes asserts, so they should not guard runtime invariants.
  - Fix: replace with explicit `if ...: raise ...` checks or structured error handling.

- [x] Medium: Reconsider Flatpak X11 fallback for passphrase entry.
  - File: `packaging/flatpak/io.github.arn-c0de.GPGMeister.yaml`
  - Issue: the Flatpak grants `--socket=fallback-x11`. Under X11, same-session clients can observe or inject UI events, which is a poor fit for a passphrase-heavy application.
  - Fix: prefer Wayland-only packaging where practical, document X11 risk clearly, and consider disabling sensitive operations when only X11 is available.

- [x] Low: Consider enabling audit hash chaining by default.
  - File: `src/gpg_meister/models/config.py`
  - Issue: audit hash-chain tamper evidence exists but defaults to disabled.
  - Fix: default `audit.hash_chain` to `true` for new configs, with migration behavior documented.

- [x] Low: Serialize `MetadataStore` access across worker threads.
  - Files: `src/gpg_meister/storage/metadata_store.py`, `src/gpg_meister/ui/*viewmodel.py`
  - Issue: one SQLite connection is opened with `check_same_thread=False`, then reused by multiple `QThreadPool` workers without an app-level lock.
  - Fix: add a `threading.RLock` around connection access or use one connection per worker/thread.

- [x] Low: Make audit hash chaining cross-process safe.
  - File: `src/gpg_meister/storage/audit_log.py`
  - Issue: the audit log lock is process-local. Two app instances with hash chaining enabled can append concurrently with stale `prev_hash`, breaking the chain.
  - Fix: use an advisory file lock around scan/append/update or restrict to a single app instance.
